# 自动洗白底 · 上线清单（2026-09）

> 跟 `docs/AI试穿-上线清单.md` 分开写：试穿还藏着，这个功能是**要放出来**的。
> 口径：默认打开、每人每天 10 张、保存衣物后自动跑、洗完自动换封面；
> **老衣物不主动补洗**（方案 A，2026-09 用户拍板）。

## 0. 发之前（先确认这四个值）

线上 `.env` 必须显式写清楚（不写就会吃代码里的默认值，行为跟你想的不一样）：

```
NORMALIZE_ENABLED=true          # 总开关；false = 入口消失 + 自动流程全停
NORMALIZE_AUTO=true             # 保存后自动跑；false = 只留手动「重新生成一张」
NORMALIZE_DAILY_LIMIT=10        # 每人每天最多几张（失败不计次）
NORMALIZE_AUTO_BACKFILL=false   # 老衣物不补洗（改 true 会按上限慢慢给所有老衣物洗，真花钱）
NORMALIZE_QUEUE=normalize       # 队列名，worker 要监听它
```

- [ ] 上面五个值确认（尤其 `NORMALIZE_ENABLED` / `NORMALIZE_DAILY_LIMIT`：代码默认值变了，
      线上不显式写就会从"关/5 张"变成"开/10 张"）
- [ ] 可选：`mysqldump` 备一份库（迁移是纯加法，但养成习惯）

## 4. 出问题怎么办

| 症状 | 处理 |
|---|---|
| 想立刻全停（省钱） | `.env` 改 `NORMALIZE_ENABLED=false` + `config:clear` → 入口消失、自动全停；已洗好的白底图不受影响 |
| 只想关"自动跑" | `NORMALIZE_AUTO=false`（手动「重新生成一张」还能用） |
| 白底图一直不出来、衣橱顶部一直挂着"正在生成" | worker 没在跑：`docker compose logs worker`；起来后队列里的任务会自己跑完。卡住的（>30 分钟）下次进衣橱会重排一次 |
| 老用户抱怨照片自己变成白底图了 | 这是自动洗的预期行为；他可以在录入页「切回原图」→ 一切回就记 `cover_choice=orig`，以后不再自动覆盖 |
| 想回滚代码 | 直接回滚即可：迁移是纯加法，老代码不认那 3 列也能跑；`NORMALIZE_ENABLED=false` 兜住行为 |

## 5. 成本与额度（发版后最坏情况）

- 单价 `wan2.7-image` **0.2 元/张**；每人每天最多 10 张 = **最多 2 元/人/天**
- **同一张原图一辈子只洗一次**（指纹缓存）：编辑、重存、切封面、试穿复用都不再花钱
- **失败不计费也不计次**（重试是免费的）；管理员不计数（不限次）
- **自动洗不占衣架**（衣架只在"新增衣物/搭配"时扣，自动换封面不算新增）
- 免费额度先扣：`qwen-image-edit` 100 张用完才计费
- 想更省：把 `TRYON_NORMALIZE_MODEL` 换成 `wanx2.1-imageedit`（0.14 元/张、500 张免费）——
  换之前建议先跑一轮质感对比：`docker compose exec app php artisan tryon:normalize <图> --model=wanx2.1-imageedit`
