# 反馈建议 → 公众号文章（2026-10）

> 用户要的：「我的」页加一个**反馈建议**菜单，点进去**直接看到**一篇公众号文章，
> 文章链接要能**动态配置**（换文章不发小程序版本）。

## 一、为什么用 web-view（以及三条绕不过去的限制）

小程序里打开公众号文章，只有 web-view 这一条路。官方文档 `web-view` 组件原文：

```
src: webview 指向网页的链接。可打开关联的公众号的文章，其它网页需登录小程序管理后台配置业务域名。
功能描述: 承载网页的容器。会自动铺满整个小程序页面，个人类型的小程序暂不支持使用。
```

翻成人话，三个硬条件：

1. **文章必须出自「已和小程序关联」的公众号**。
   别的公众号的文章、普通网页都不行 —— 普通网页要配业务域名，而 `mp.weixin.qq.com`
   根本没法配业务域名（校验文件放不进去）。**这条是最容易踩的坑**：
   拿一篇别人的公众号文章填进去，线上就是「该网页无法在小程序内打开」。
2. **个人主体的小程序根本不能用 web-view**。如果是个人主体，这个方案直接不通，
   得换：客服会话自动回复文章 / 复制链接。
3. web-view 会**铺满整页**，`navigationStyle: custom` 对它无效（导航栏只能用原生的）。

## 二、链接怎么配（改完立刻生效，不用发版）

三层，跟文案表 / 插画表**完全同一套思路**：

| 层 | 在哪 | 作用 |
| --- | --- | --- |
| 1 内置默认 | `app/Services/Links.php` 的 `DEFAULTS` | 兜底，默认全是**空串** |
| 2 服务器文件 | `storage/app/links.json` | **你在服务器上改这个文件，立刻生效** |
| 3 接口下发 | `GET /api/links`（免登录） | 小程序启动拉一次，存本地 |

换文章的操作（线上）：

```bash
# 只在第一次需要：把当前生效的全量链接落成文件
php artisan links:export
# 之后直接改这个文件，存盘即生效（小程序重开一次就能看到）
vi storage/app/links.json
```

```json
{
    "mine.feedback_article": "https://mp.weixin.qq.com/s/xxxxxxxxxxxx"
}
```

- 只写想改的那条就行，没写的自动用默认值
- **留空 = 小程序里不显示这个菜单**（`wx:if="{{feedbackArticleUrl}}"`）——
  没配链接时点进去白屏，比少一行入口更糟
- 文件写坏了/不是合法 JSON → 退回默认值，不会把小程序搞崩

前端拿链接：`utils/links.js`

```js
const links = require('../../utils/links.js')
links.ensure().then(() => this.setData({ feedbackArticleUrl: links.url('mine.feedback_article') }))
```

拉不到（没网/接口挂了）用**上次存下来的**；缓存也没有就是空串 → 菜单不显示。

## 三、页面与白名单

- `pages/mine/mine.wxml`：菜单项「反馈建议」，在「联系客服」上面一行，
  图标复用已有的 `.ico-feedback`（气泡描边）
- `pages/mine/mine.js`：`onFeedbackArticle()` → 跳
  `/pages/webview/webview?url=<encodeURIComponent(链接)>&title=反馈建议`
- `pages/webview/webview`：整页 `<web-view src>`，**域名白名单只有 `mp.weixin.qq.com`**

白名单是故意的：这个页本质是「外链壳子」，放开成任意域名等于给小程序开了个浏览器，
审核会问、也容易被人拿来套壳。要加新域名就改 `ALLOW_HOSTS`（要发版，属于例外情况）。

兜底：`bind:error` 触发（文章被删 / 被当成非关联公众号拦掉）时，整页换成一张卡片
「文章打不开 + 复制链接」，文案走文案表 `webview.*`。

## 四、上线顺序

1. **后端先发**（新增路由 `GET /api/links` + `links:export` 命令，不动数据库、**没有迁移**）
2. 服务器上 `php artisan links:export` → 把真实文章链接写进 `storage/app/links.json`
3. 小程序发版（新增了 `pages/webview/webview` 这个页面，必须提审）
4. 真机验收（见下）

## 五、验收清单（必须真机，开发者工具看不可靠）

真机最容易两个不一样的：

- **开发者工具里 web-view 不校验公众号关联**，看着能开、真机可能白屏 —— 一定要手机上看
- 未登录状态也要能看到「反馈建议」（`/api/links` 是免登录的，别顺手挪到 auth 组里）

清单：

- [ ] 未登录进「我的」→ 菜单里有「反馈建议」
- [ ] 点进去文章整页能看、能上下滑、右上角「…」能分享/在浏览器打开
- [ ] 返回后「我的」页正常（web-view 返回不会重跑 onLoad，别在这里挂一次性逻辑）
- [ ] 把 `links.json` 里的链接改成一条**别的公众号**的文章（或删掉）→ 小程序重开：
      菜单消失（留空）或点进去看到「文章打不开」兜底卡片（无效链接），**不白屏**
- [ ] 断网进「我的」→ 菜单按上次缓存的链接显示，不报错
