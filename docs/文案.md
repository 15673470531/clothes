# 提示语文案表（2026-09）

> 小程序里所有提示语（toast / 弹窗 / "加载中"这类）**都不写在小程序代码里**，由后端下发。
> 改一句话不用重新发版，改完让用户重开一次小程序就生效。

## 一、三层文案，优先级从低到高

| 层 | 放在哪 | 说明 |
| --- | --- | --- |
| 内置默认 | 后端 `app/Services/Texts.php` 的 `DEFAULTS` | 保底：任何情况下都有话可说。改这个要发后端 |
| 服务器文件 | `storage/app/texts.json` | **你平时改文案就改这里**，改完立刻生效（接口每次读文件） |
| 小程序本地默认 | 小程序 `utils/texts.js` 的 `DEFAULTS` | 兜底：后端连不上时的提示（"网络异常""登录失效"这类**只能**本地有） |

生效顺序：`storage/app/texts.json` > 后端 DEFAULTS > 小程序本地 DEFAULTS（只在前两层都拿不到时用）。

## 二、怎么改文案（线上，最常用）

```bash
# 1 首次：把当前全部文案落成文件（已经有了就跳过）
php artisan texts:export        # 生成 storage/app/texts.json

# 2 打开 storage/app/texts.json，改你想改的那几条（**只留要改的也行**，其余自动用默认）
#    例：{ "mine.logged_out": "拜拜，下次再来" }

# 3 不用重启、不用 clear —— 接口每次都读这个文件，保存即生效
curl https://<域名>/api/texts | head    # 想确认就 curl 一下
```

用户端要**重开一次小程序**才会拉到新文案（文案在启动时拉一次，之后存本地）。

## 三、文案里带数字怎么办

用户 2026-09 定的口径：**后端能拼就后端拼，拼不了才给占位符**。

| 情况 | 做法 | 例子 |
| --- | --- | --- |
| 数字在后端（奖励个数、上限） | 后端直接拼好整句下发 | 签到接口的 `toast` = `签到成功 +2 个衣架`（+2 来自 `config/quota.php`） |
| 数字只有前端知道 | 文案里留 `{xxx}`，前端替换 | `还有 {n} 个衣架`、`已移出「{name}」`、`准备照片 {i}/{n}` |

⚠️ 改了带 `{xxx}` 的文案，**占位符名字不能改**（前端按名字替换，改了就替换不上，界面上会露出 `{n}`）。
反过来改文案表里没写的占位符也没用。

## 四、接口

```
GET /api/texts        # 免登录（登录前的提示也要有文案）
→ { code:0, data: { texts: { key: 文案, ... }, version: "md5", count: 119 } }
```

- `version` 是内容指纹：没变小程序就不重写本地缓存
- 新增文案：只往 `DEFAULTS`（后端 + 小程序两端）加 key 即可，服务器上的旧文件不用补

## 五、代码位置

| 地方 | 文件 |
| --- | --- |
| 后端默认文案 / 读文件 / 取值 | `app/Services/Texts.php` |
| 后端接口 | `app/Http/Controllers/Api/TextsController.php` + `routes/api.php` 里 `Route::get('texts')`（**在 auth 中间件之前**） |
| 导出命令 | `app/Console/Commands/TextsExport.php`（`php artisan texts:export`） |
| 小程序取文案 | `utils/texts.js`（`T.t('key')` / `T.t('key', {n: 3})`），启动时 `app.js` 的 `onLaunch` 里 `load()` |
| 自检 | `node /tmp/check-texts.js`（比对前后端文案是否一一对应、有没有用错 key） |

## 六、注意

1. **改 key 名字 = 破坏性改动**：小程序里是硬编码的 key，改名必须两端一起改 + 发版。改文案内容随便改。
2. **前后端 DEFAULTS 必须一致**：改了后端 `Texts.php` 的默认值，同步改小程序 `utils/texts.js`（自检脚本会比对，跑一下就知道）。
3. **页面上成段的说明文字**（比如衣架说明页的"什么是衣架"）**还没走文案表**，仍然是小程序里写死的；
   要一起搬的话再说（它们不是"提示语"，改动频率低）。
4. toast 标题有长度限制：微信大概 14 个汉字以内不换行，写长了会被截断。
