# 首版衣物录入行为观察

入口：管理员「我的 → 数据统计 → 首次录入行为观察」。支持近 1、7、30 天，逐步转化、取消/异常计数和最近 20 次访问时间线。

上线先部署后端并运行 `php artisan migrate --force`，再发布小程序。确保已有的每分钟 `php artisan schedule:run` 调度正常；新增 `usage-events-prune` 每日 03:30 清理超过 30 天的明细。历史行为无法补录。

- POST `/api/usage/events`：登录后批量最多 30 条，服务端绑定当前账号、字段白名单、事件 ID 去重和限流。管理员事件排除。
- GET `/api/admin/usage?days=7`：仅管理员可读，最多分析最近 20000 条，截断时提示。普通账号返回 403。
- 一段会话以 30 分钟无活动切分，原生预览/照片选择隐藏页面不会结束会话。客户端最多暂存 100 条，超过 24 小时未上报的事件丢弃；上报失败不阻断业务，后续触发重试。
- 漏斗要求同一会话按顺序完成步骤；已登录回访也计入起点，空衣橱不代表新注册。跨会话继续录入、事件丢失都可能导致漏斗不完整，不能把最后一步解释成退出原因。
- 保存成功表示衣物记录提交成功；照片后台上传失败单列。错误次数按尝试计，包含重试；并非出错用户数。
- 不记录图片、路径、用户输入、备注或原始异常文本。仅记录内部账号 ID、会话/事件 ID、页面、步骤、白名单来源/结果、错误码、数量、耗时、时间。用户可在「关于 → 数据与账号」查看说明。

验证：`php artisan test --filter='UsageTest|ItemDetailsTest|QuotaTest'`。测试使用 sqlite 内存数据库。
