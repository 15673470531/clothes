## 二、图放哪：**包内本地图为准**，后端下发只作可选覆盖（2026-09 真机踩坑后定的）

真机白屏过一版，原因（两个都可能，所以两个都堵了）：
1. **iOS 小程序的 image 组件不认 webp** —— 第一版图是 webp，开发者工具里正常、真机白屏
2. 网络图受 **downloadFile 合法域名**限制：OSS 域名不在白名单里就加载不出来
   （开发者工具里通常勾了"不校验合法域名"，看不出这个问题）

所以现在的口径：

```
图片本体：小程序包内 images/art/*.png|jpg     ← 一定能显示（不依赖网络/白名单/格式）
        ↑ 有后端 URL 时优先用后端（想"服务器换图不发版"才需要它）
GET /api/assets → { items: {key: url}, version }   （免登录；**默认全空串 = 用包内本地图**）
        ↑ 页面用 assets.pick(key)：有 URL 用 URL，没有用本地图
        ↑ 图加载失败（binderror）→ assets.fallback(key) 换回本地图，绝不空一块
```

- 想启用"服务器换图不发版"：把 **PNG/JPG**（别用 webp）传到 OSS，URL 填进
  `storage/app/assets.json`（或 `Assets::DEFAULTS`）即可，小程序下次启动生效
- 分享封面（`images/share-cover.jpg`）本来就在包内，不受上面这些影响

### 早期方案（已改，留个记录）

```
数据库/代码里没有图，只有 URL：
  app/Services/Assets.php 的 DEFAULTS   ← 内置默认（现在是 OSS 上的地址）
  storage/app/assets.json               ← 服务器上可覆盖（只写要改的那几条，立刻生效）
        ↓
  GET /api/assets  →  { items: {key: url}, version, count }     （免登录）
        ↓
  小程序 utils/assets.js：启动拉一次存本地（key=assetUrls）→ 拿不到就用上次存的 → 都没有就不显示图
```

- **换图/撤图不用发小程序版本**：`php artisan assets:export` 落出 assets.json，改里头的 URL 即可
  （值写成 `""` = 这张不显示，前端自动退回纯文字空态）
- **分享封面必须在包内**（`images/share-cover.jpg`）：转发面板要立刻拿到图，不能等网络
- ⚠️ **key 里带点**（`empty.wardrobe`）：PHP 端别用 `data_get()` / `->json('data.items.empty.wardrobe')`
  这种点语法取值（会被当成三级路径、永远 null）。`Assets::get()` 或按下标取都行

### 附：图片缓存与"换图"的铁律（2026-09）

| 图从哪来 | 有没有缓存 | 换图怎么生效 |
| --- | --- | --- |
| **小程序包内**（`images/art/*`、`images/share-cover.jpg`） | 没有网络请求，"包就是图"，更新版本即最新 | 换图 → 发新版 |
| **网络图**（`<image src="https://...">`，如启用远端覆盖后的 OSS 图） | **微信会缓存**（按响应头，多数情况自己也存一段时间，官方没给时长承诺） | **换 URL**（新文件名或加 `?v=版本`），**别覆盖同名文件** |
| 用户衣物照片 | 显示时优先用本机文件；本机没有才去云端拉（云端图也会被缓存） | 照片都是**随机文件名**（`ImageStorage`），天生不撞缓存 |

铁律：**同名覆盖 = 用户可能一直看旧图**。所以
- 后端下发的那几个 URL，换图时让它跟着变（我们的 `GET /api/assets` 有 `version` 指纹，
  前端要强制刷新的话可以在远端 URL 后面拼 `?v=<version>`）
- 排查"怎么还是旧图"：开发者工具 → 清缓存 → 清除数据缓存；真机 → 删掉小程序重新进

## 三、图是怎么来的（以后要加图照这个来）

> 出图**必须出 PNG/JPG**：iOS 真机不认 webp。透明底的空态用 PNG，横幅/封面用 JPG。

1. **生成**：阿里云百炼 DashScope 文生图 `wanx2.1-t2i-turbo`（异步提交 + 轮询），
   提示词模板 = 主体描述 + 风格串：
   > 扁平矢量插画，柔和莫兰迪配色：主色深紫 #5D4C7C、浅紫 #C9BFE0、暖白背景 #FBF8F4、
   > 少量珊瑚橙 #E8A87C 点缀；极简构图，留白多；细线条 + 色块平涂；没有人物、没有任何文字

   负面词里**一定要写"任何文字/汉字/字母/数字/标题/水印"** —— 不给它就自己往图里加乱码字
   （第一次生成的日历图就带了一行"MRENCLLARAT"）。日历这种"天生带字"的结构，
   干脆换成不含标题栏的形状（方格板/小本子）。
2. **后处理**（`/usr/local/bin/python3` + Pillow，脚本见 git 里的记录）：
   - 去背景：四角 floodfill 把纯色背景抠成透明（内部浅色衣物不会被误伤）
   - 裁切：按内容 bbox 裁 + 8% 留白，统一缩到高 560（UI 里用 `mode="widthFix"` 按宽度显示）
   - 导出 WebP（quality 88）→ 单张 6~23 KB
   - 分享封面：裁成 5:4 → 750×600，用 PingFang/Hiragino 叠 logo + 主宣传语 → JPEG
3. **上传**：把文件喂给 `App\Services\ImageStorage::putBinary(..., 'webp', 'assets')`（配了 OSS 就进 OSS），
   拿到 URL 写进 `Assets::DEFAULTS`
4. **绑定**：页面里 `assets.ensure().then(() => this.setData({ emptyPic: assets.url('empty.xxx') }))`
